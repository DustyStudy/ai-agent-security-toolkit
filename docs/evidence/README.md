# Test evidence

Dated, per-release evidence of what was tested and what the results were. Each release folder
holds Markdown (readable on GitHub), a self-contained HTML page (open it in a browser, archive
it, print it) and a screenshot of that page. All of it is generated by
[`scripts/evidence_report.py`](../../scripts/evidence_report.py) from the files the tools
already write: pytest's JUnit XML, coverage.py's XML and `agentsec fuzz --json` reports.

## What each page shows

- **Tests and simulator.** The full pytest suite and line coverage on the tagged commit, plus
  the fuzz matrix against the built-in simulators. The simulators are not models: `builtin:naive`
  obeys every injection, so it shows the matrix is live (100%), and `builtin:guarded` shows what
  the controls stop when the "model" is fully compromised. Its *containment* column (tool misuse,
  exfiltration and prompt leak) must be 0; the rest of its ASR is the model echoing injected
  text, which the controls are not meant to stop (see the README's simulator results).
- **Live model.** The same matrix against a real model on local hardware, bare and behind the
  full stack, with the model, runtime, GPU and seed on the page. Method and discussion are in
  [docs/PROOF.md](../PROOF.md).

The CI matrix (Linux on Python 3.11-3.14, Windows, macOS, fuzzing, the container smoke test and
the security scans) is the authoritative record for each commit. Every CI run also produces this
report: open the run on the Actions tab for the summary, and download the `test-report-*`
artifact for the HTML page, the JUnit XML and the coverage report.

## Regenerate

```bash
mkdir -p reports
pytest --junitxml=reports/junit.xml --cov=agentsec --cov-report=xml:reports/coverage.xml
agentsec fuzz --target builtin:guarded --json reports/fuzz-guarded.json
agentsec fuzz --target builtin:naive --json reports/fuzz-naive.json
python scripts/evidence_report.py --junit reports/junit.xml --coverage reports/coverage.xml \
  --fuzz builtin:guarded=reports/fuzz-guarded.json --fuzz builtin:naive=reports/fuzz-naive.json \
  --md reports/summary.md --html reports/report.html
```

`reports/` is git-ignored. To add a release here, generate into `docs/evidence/vX.Y.Z/` with
`--commit` naming the tagged commit, take a screenshot of the HTML page, and add a row above.
The `readme-*.png` images (light and `-dark`) are cropped from the same pages for the main README; regenerate them with the release. Raw fuzz JSON is not committed: it holds every attack prompt and model answer, and the
summaries are what a reader needs. Keep it with the release artifacts if you need it.
